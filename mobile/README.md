# PVL Hub — iOS / Android App (Capacitor)

This folder wraps the existing PVL Hub web app in a native shell using
[Capacitor](https://capacitorjs.com/), so you can open it in **Xcode**, ship it
to the App Store, and get **native push notifications** and **deep-linking**
into the sibling PVL apps (Fantasy Card Game, Manager Game).

Because it reuses the exact web app, you don't rebuild any screens — the native
app loads the same HTML/CSS/JS and the `window.PVLNative` bridge
(`js/native-bridge.js`) lights up the native features automatically.

---

## Prerequisites (do this on a Mac)

- macOS with **Xcode** installed (+ Command Line Tools)
- **CocoaPods** (`sudo gem install cocoapods`)
- **Node.js** 18+

> The native `ios/` project is generated by `npx cap add ios`, which requires
> Xcode/CocoaPods and therefore must be run on a Mac. It is intentionally not
> committed here — generate it on your machine.

---

## First-time setup

```bash
cd mobile
npm install          # install Capacitor + plugins
npm run copy-web     # copy the web app (repo root) into mobile/www
npx cap add ios      # generate the native Xcode project (ios/)
npm run ios          # copy-web + cap sync + open in Xcode
```

Then in Xcode: select a signing team, pick a simulator or device, and Run.

Every time you change the web app:

```bash
npm run sync         # re-copy web assets + cap sync
```

### Optional: wrap the LIVE site instead of bundling

To have the app load your deployed site (so web updates appear instantly, no
re-bundling), add a `server` block to `capacitor.config.json`:

```json
"server": { "url": "https://<your-pvl-hub>.netlify.app", "cleartext": false }
```

Bundling (the default) is better for App Store review and offline launch;
`server.url` is better for fast iteration.

## Push notifications

The web notification center (`js/notifications.js`) already has a "Push alerts
for my teams" toggle. Inside the app it calls `PVLNative.registerPush()`, which
requests permission and registers with APNs.

To finish enabling push:

1. In Xcode → target → **Signing & Capabilities**, add **Push Notifications**
   and **Background Modes → Remote notifications**.
2. Create an **APNs key** in the Apple Developer portal and wire it to your
   push provider (e.g. Firebase Cloud Messaging or your own APNs sender).
3. In `js/native-bridge.js`, the `registration` listener logs the device token
   — POST it to a backend endpoint so the server can target the device when a
   favorite team has a game (this is the server side of the reminders the
   notification center shows locally today).

## Deep-linking between the three apps

The launcher (`js/launch.js`) defines a URL scheme per product:

| Product            | Scheme          |
|--------------------|-----------------|
| PVL Hub            | `pvlhub://`     |
| PVL Manager Game   | `pvlmanager://` |
| PVL Fantasy Cards  | `pvlcards://`   |

To make "Play Manager Game / Play Card Game" open the installed native app
(with an App Store fallback):

1. **This app** registers `pvlhub` under *Info → URL Types* in Xcode so the
   sibling apps can open it back.
2. Fill in the real **App Store URLs** and confirm the **schemes** at the top
   of `js/launch.js` (`PRODUCTS`) once the Manager and Card Game apps are
   published. Until then the launcher gracefully opens the web version.
3. For nicer universal links (https:// links that open the app), add an
   **Associated Domains** capability (`applinks:<your-domain>`) and host an
   `apple-app-site-association` file on the web domain.

## What's here

```
mobile/
├── package.json            # Capacitor deps + helper scripts
├── capacitor.config.json   # app id, name, webDir, push config
├── copy-web.js             # copies the repo-root web app into www/
├── www/                    # bundled web app (generated by copy-web)
└── README.md               # this file
```

The web-side bridge lives at repo root in `js/native-bridge.js` and is loaded
by the main pages; it only activates inside the native app.
